# 本地任务工作流

Hub 按规则接收事件、管理执行轮次和确认卡。Worker 在项目目录运行 Agent 并保存执行日志。loopj 看板提供任务检索、人工确认、会话交接和分支操作。

## 事项和路由

按事项执行时，规则名和 `subject` 确定任务归属。同一 Issue 可以按不同规则进入各自的任务。事件来源和事件 ID 用于去重，后续评论可触发新的执行轮次。看板使用任务 ID 区分匹配到不同规则的同一个 Issue。

规则的 `when` 定义来源和事件类型或定时条件，`to` 选择 Agent，`cwd` 指定工作目录。项目可以在 `cwd` 下维护自己的 `AGENTS.md`。代码任务可以在 `repositories` 里声明本机仓库与基线分支。

## 开发与排查

启用 `planApproval` 的任务先调研需求和影响范围，提交开发方案确认卡。负责人批准后，Worker 按获批范围执行。启用 `prepareWorktrees` 时，Worker 为获批仓库准备独立 worktree，并核对基线提交。审批只覆盖明确列出的改动范围。

排查使用项目已授权的只读数据和日志工具。若需修改代码或执行对外操作，按项目配置完成对应确认。项目可以通过 `test-delivery.json` 声明测试分支和地址，见[示例](../examples/test-delivery.json)。

## 工作区和会话

首次准备 worktree 时，Worker 可以用公开 Issue 编号生成短分支，例如 `fea_DEMO123`。后续轮次沿用已登记的分支。用户可以在看板确认将需求分支交给原项目目录调试，再交回 worktree。已提交改动随同一分支保留。

支持的 Codex 会话可在 App 接手后交回 CLI，交回时可以附带本地处理记录。看板在任务详情展示执行轮次、日志和确认历史。已结束一轮的任务仍可按后续事件或人工操作续办。

## 交付和结案

配置 Octo 后，可采集 Issue、预览规则匹配、为指定规则补派任务，并在确认后发送提测或上线通知。手动结案会关闭剩余的确认卡，后续事件保留记录。结案和外部 Issue 状态分别管理。

更多字段和审批约束见[协议](protocol.md)，Octo 接入见[采集器文档](octo-collector.md)。
